# Carromscore v3.3.1

Patch release: surface RTDB write errors and roll back local state
on denial. Diagnostic + defensive plumbing for a report during
v3.3.0 soak where an organiser's newly-created tournaments and
players appeared in the admin list, then vanished on next page
load — a silently-denied RTDB write masqueraded as success.

**APK SHA-256**: `2420fe4f5c4417cf211e3347c746b665018add70a476cbc0cb4b04679c5e70c8`

## What changed

**Silent-swallow → surfaced.** `createOrTouchTournament` (in
`src/lib/tournaments.ts`) and `createPlayer` (in
`src/lib/players.ts`) used to catch every Firebase write error and
discard it. When the RTDB rule denied a write (auth token not
attached in time, `organiserRoles` missing, etc.) the local
`memoryStore` push made the record visible in the admin list, but
it never landed in Firebase — so on a fresh page load (which
rehydrates from RTDB only) it vanished.

Both functions are now `async` and return
`{ ok: true; record/player } | { ok: false; error }`. The
AdminTournaments and AdminPlayers add-flows await the outcome and
flash the RTDB error message to the umpire on denial.

**Roll back on denial.** On `ok: false` the local push is undone
before the outcome returns — so the admin list never shows a
phantom record that vanishes on refresh.

## Migration notes

- **No breaking changes.** The wrap of `createPlayer` and
  `createOrTouchTournament` as `async` affects only the two
  admin-panel callers (AdminPlayers, AdminTournaments), both
  updated in this release.
- **APK bump** (versionCode 41 → 42, versionName 3.3.0 → 3.3.1)
  for TWA parity; wrapper otherwise unchanged.
