# Carromscore v3.4.0

Optional Firebase Analytics, off by default, with a first-run
consent banner. Also a new Settings menu on the home screen for
revoking consent later.

This is the first data Carromscore has ever collected across
sessions. It is opt-in, off by default, and revocable at any time.

## What changed

- **Opt-in Firebase Analytics.** New consent banner on the home
  screen the first time a user loads the app. Tap **Allow** to
  enable Firebase Analytics; tap **No thanks** to keep the app
  in its pre-v3.4 posture (no beacons). The Analytics SDK is
  dynamic-imported and never loaded for users who decline —
  same-bundle guarantee via a code-split chunk.
- **Settings menu.** A new gear icon in the home footer opens a
  small popover with a single toggle: **Share usage analytics**.
  Reflects the persisted consent, and revoking it stops beacons
  immediately (calls `setAnalyticsCollectionEnabled(false)` on the
  already-loaded SDK).
- **Screen-view events on every route.** The `home`, `lobby`,
  `admin`, `setup`, `score` screens fire a `screen_view` event on
  mount. Firebase's default report groups them by `screen_name`
  rather than by URL — so a `/score/?mid=abcd` load doesn't show
  up as a unique screen per match.
- **Spectator opt-out.** Public `/live/{mid}` link opens (from a
  WhatsApp / Slack share) are dropped client-side. Only sessions
  that touch the setup form or admin surface count.
- **Docs revised, honestly.** [README.md](../../README.md#L27) and
  [docs/dev/architecture.md](../dev/architecture.md#L66) no longer
  say "no PII, no tracking" as a blanket. Both explicitly call
  out the optional opt-in flow. A new
  [docs/dev/analytics-setup.md](../dev/analytics-setup.md)
  documents what's collected, the consent lifecycle, how to
  enable / disable at the console level, and where to read the
  data.

## Migration notes

- **No breaking data changes.** No RTDB schema fields added or
  removed. Firebase Analytics is a separate GA4 property — nothing
  in `/tournaments`, `/players`, `/matches`, `/live` changes.
- **New repo secret required for CI:**
  `PUBLIC_FIREBASE_MEASUREMENT_ID`. Missing value = analytics
  silently skipped (the consent banner still renders but the
  Allow tap does nothing). Setup docs:
  [docs/dev/analytics-setup.md](../dev/analytics-setup.md).
- **Bundle size.** Adds ~40 KB gzipped for the analytics chunk,
  BUT only downloaded for users who opt in. Users who decline
  never see the SDK on the wire.
- **No APK bump.** Wrapper unchanged; existing v3.3.6 APK installs
  auto-update on next launch.
