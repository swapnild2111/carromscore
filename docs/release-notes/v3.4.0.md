# Carromscore v3.4.0

Firebase Analytics — running in the background so the maintainer
can see which regions use the app. No account linkage, no ad
tracking, no data sold.

## What changed

- **Firebase Analytics is on.** Geography, device type, session
  events, and screen views (`home`, `lobby`, `admin`, `setup`,
  `score`) are collected per session. Read the data in the
  Firebase console → Analytics section:
  <https://console.firebase.google.com/project/carrom-score/analytics>.
- **No account linkage.** `setUserId` is never called; two
  sessions on one phone look like two anonymous sessions.
- **Spectator opt-out.** Public `/live/{mid}` link opens from a
  shared WhatsApp / Slack link are dropped client-side. Only
  sessions that touch the setup form or admin surface count
  toward the DAU / MAU numbers.
- **Support link renamed to Donate.** Same Ko-fi target, clearer
  wording — "Support" was reading as a bug-report / feedback
  channel for some users. Applies to home, lobby, admin footers
  and the help page section.
- **Docs revised, honestly.** [README.md](../../README.md#L27) and
  [docs/dev/architecture.md](../dev/architecture.md#L66) call out
  the collection explicitly. A new
  [docs/dev/analytics-setup.md](../dev/analytics-setup.md)
  documents what's collected, how to disable Analytics
  browser-side, and how to turn it off at the console level.

## Migration notes

- **No breaking data changes.** No RTDB schema fields added or
  removed. Firebase Analytics is a separate GA4 property — nothing
  in `/tournaments`, `/players`, `/matches`, `/live` changes.
- **New repo secret required for CI:**
  `PUBLIC_FIREBASE_MEASUREMENT_ID`. Missing value = analytics
  silently skipped (SDK isn't loaded). Setup docs:
  [docs/dev/analytics-setup.md](../dev/analytics-setup.md).
- **Bundle size.** Adds ~40 KB gzipped for the analytics chunk,
  code-split so it loads on the first screen mount rather than
  in the initial bundle.
- **APK bump** (versionCode 47 → 48, versionName 3.3.6 → 3.4.0)
  for TWA parity; wrapper otherwise unchanged.

## What was in beta but didn't ship

Earlier v3.4.0 beta iterations had an opt-in first-run consent
banner and a Home → Settings toggle to revoke consent. Both were
removed before the release cut — the data collected is limited
enough that a consent prompt was more theatre than protection,
and it introduced a "gear icon" on the home screen that muddied
the UX. Users who want to block Analytics can do so browser-side
(Firefox tracking protection, uBlock Origin, Do Not Track).

Also during the beta soak: the live-match popup header wrapped
badly when a tournament had rounds — long title pushed the OBS
button off the right edge of the viewport. Fixed with a two-row
header layout so the actions strip never gets squeezed.
