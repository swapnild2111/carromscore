# Carromscore v3.7.0

Keyboard-first UX, polished print pack, bracket slot completion
display, and a bundle of bug fixes from tournament-day testing.

Web changes only — existing v3.6.1 APK installs auto-update on
next launch. TWA bumped for parity; fresh APK download is optional.

## Keyboard navigation

Full keyboard control across the home screen setup form:

- **Mode cards** (Singles / Doubles / Practice) — Tab to focus,
  arrow keys to switch modes, gold focus ring on the selected label.
  Previously `display:none` on the radio input removed them from the
  tab order entirely; now `opacity:0; width:1px; height:1px`.
- **Player name picker** — ArrowDown/Up navigate the autocomplete
  dropdown with a visible gold highlight, Enter/Space selects,
  Escape closes, Tab selects the highlighted item and moves focus
  forward. A `suppressPickerBlur` flag prevents the dropdown from
  closing mid-navigation when focus briefly leaves the input.
  Also fixed: the `<button>` inside the suggestion list was missing
  its closing `>`, making it a self-closing tag with no content —
  clicks and key events were silently dropped.
- **Tournament picker** — same arrow-key navigation and highlight
  as the player picker. Previously had no keyboard support at all.

## Print pack

### Per-match QR mode

- Cards now show **Match 1 / Match 2 / …** (globally sequential
  across all rounds) instead of "Board 1 / Board 2". The board
  labels were misleading: in per-match mode there is no fixed board
  assignment — players take any free board.
- Cover-page schedule table shows **M1 / M2 / …** in the first
  column when in per-match mode, and the column header changes from
  "Board" to "Match".

### Schedule table layout

- Player names in the matchup column no longer stretch to fill the
  full table width. "Swapnil Deshpande vs Yuvaraj Eshwaramoorthy"
  now reads as a natural inline pair instead of two names anchored
  at opposite ends of a 1000px row.

### Reports print

- Print button now produces a polished A4 landscape document:
  - Tournament name + round + date injected as a bold header.
  - Stat tiles in a horizontal strip; podium tile gold-tinted.
  - Both tables: black-on-white, 1px borders, zebra alternating
    rows on the matches table, gold tint on the leaderboard top row.
  - Winner tags swap to print-safe blue / red / brown.
  - Per-round accordion: all sections forced visible; chrome
    (carets, copy buttons) hidden.
  - Lobby header ("← Back · Lobby") and tab strip ("Now playing /
    History / Reports") hidden from printed output.

## Reports tab

- **Blank stat tile fixed**: removing the Tournaments tile left a
  ghost column in the 6-column grid. Grid updated to 5 columns
  (3 number tiles + podium spanning 2) — no gap.
- Tournaments stat tile removed (was always "1" when filtered to a
  specific tournament — no information value).

## Bracket

- **Completed slot display**: when a match ends, the bracket row
  now shows a blue "complete" pill with the winner name and set
  score (e.g. `Swapnil Deshpande 2–1`) instead of disappearing.
  The `markPlannedComplete()` function writes `completedAt`,
  `completedBy`, and `result` to `/planned/{mid}` instead of
  deleting the record.
- **Completed slots excluded from QR scan resolution**: the
  `resolvePlannedByBoard` path skips records with `completedAt` set
  so a re-scan after a finished match doesn't re-open the same slot.
- **AdminTournaments planned count**: completed slots excluded from
  the per-round and per-key counts shown in the bracket panel badge.

## Bug fixes

- **Match archive "score visible on this device only"**: `endedAt`
  RTDB validate rule was `<= now`, which rejected writes when the
  device clock was slightly ahead of Firebase server time.
  Widened to `<= now + 30000` (30 s tolerance). Requires the rule
  to be published in Firebase Console.
- **Tournament delete cascade**: deleting a tournament now also
  deletes its `/planned/{mid}` records. Previously orphaned records
  caused the bracket to show a stale count (1) when the tournament
  was recreated with the same name.
- **`$derived` → `$derived.by`**: two tournament-picker derived
  values used `$derived<T>(fn)` which stores the arrow function as
  the value instead of calling it — caused a runtime crash
  ("s(...) is not a function") on the home screen.

## RTDB rules

- `/planned/{mid}`: new fields `completedAt`, `completedBy`,
  `result` (with `setsA`, `setsB`, `winner`) validated.
- `/matches/{id}`: `endedAt` validate widened to `<= now + 30000`.

Publish the updated `database.rules.json` in Firebase Console.

## Migration notes

- **RTDB rule publish required** — see above.
- **No data migration** — existing planned records remain valid;
  new fields are optional additions.
