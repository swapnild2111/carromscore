# Carromscore v3.4.11

Two independent fixes: (1) the offline banner no longer gets stuck
after Chrome mobile suspends the tab in the background; (2) archived
matches now render their per-set totals from the board-by-board log
rather than a possibly-stale summary field, so a phantom SET+ tap
during play can't create a permanently wrong scorecard.

<!-- apk-required: false -->

Web changes only — existing v3.4.10 APK installs auto-update on
next launch.

## What changed

- **Aggressive banner-hide on resume.** Chrome mobile suspends the
  whole tab process while backgrounded. On foreground resume, the
  Firebase `.info/connected` socket state can lag reality, leaving
  the "You're offline" banner stuck. On any visible-after-hidden
  transition that lasted >2s, we now trust `navigator.onLine`
  immediately: if the browser says we're online, hide the banner
  without waiting for the SDK to catch up. The reconnect nudge
  fires in parallel; if we're actually offline, the banner reappears
  as soon as Firebase confirms.
- **Set counts + winner now derived from boardLog** when boardLog
  is present. Historically `setsA`/`setsB`/`winner` were written
  independently by the scoring engine at End Match time. A stray
  SET+ tap during play — against a side that was momentarily ahead
  mid-set but ultimately lost — could commit a phantom set that
  persisted after the actual set ended and points reset. The
  boardLog is untouched by such mistakes and stays the authoritative
  source. New behaviour: when boardLog exists, the history list card
  and popup header pill compute setsA/setsB/winner from per-set
  boardLog totals. When boardLog is missing (legacy records), the
  stored fields are used as before — no regression.
- Match `-P-tT5XCEnG5uAuJR81U` (2026-11-24, DKCF doubles) is the
  motivating case: boardLog shows Azam's team winning all 3 sets;
  stored summary said 2-1. Popup now renders the truth (3-0).

## Migration notes

- No RTDB schema changes, no rule changes.
- No data migration — the reconcile happens at read time; stored
  records are unchanged. If a future write path re-persists a match
  (admin edit, sync-queue replay), the fresh write reflects reality
  because ScoreBoard already writes both fields consistently from
  live state.
- **APK bump** (versionCode 58 → 59, versionName 3.4.10 → 3.4.11)
  for TWA parity; wrapper otherwise unchanged.
