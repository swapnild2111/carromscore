# Carromscore v3.4.11

Two independent fixes: (1) the offline banner no longer gets stuck
after Chrome mobile suspends the tab in the background; (2) archived
matches now render their per-set totals from the board-by-board log
rather than a possibly-stale summary field, and the same reconcile
runs at write time so no future edit — organiser or admin — can
introduce a divergence.

**APK SHA-256**: `3304060ae26cb38fb005703b4e6064812e3bf152dbe094345624df57b3a55932`

## What changed

- **Aggressive banner-hide on resume.** Chrome mobile suspends the
  whole tab process while backgrounded. On foreground resume, the
  Firebase `.info/connected` socket state can lag reality, leaving
  the "You're offline" banner stuck. On any visible-after-hidden
  transition that lasted >2s, we now trust `navigator.onLine`
  immediately: if the browser says we're online, hide the banner
  without waiting for the SDK to catch up. The reconnect nudge
  fires in parallel; if we're actually offline, the banner
  reappears as soon as Firebase confirms.

- **Set counts + winner now derived from boardLog** in three
  places — read, edit, and write:
  - **History-card + popup header pill** (read-time): computed from
    per-set boardLog totals. When a stored `setsA`/`setsB`/`winner`
    disagrees with what the boardLog shows, the popup shows the
    truth.
  - **MatchEditModal** (edit-time): the sets/winner input fields
    are now computed-only, next to the already-computed
    finalPointsA/finalPointsB/boardCount cells. Editing a boardLog
    row auto-updates every summary field. Admins have no way to
    save a set count that disagrees with the rows.
  - **`finishMatch` + `updateMatch`** (write-time): both entry
    points reconcile the summary against boardLog before writing.
    A stale or bad set-count coming from any client is corrected
    at persistence.

- Motivating case: match `-P-tT5XCEnG5uAuJR81U` (DKCF doubles,
  2026-11-24). boardLog shows Azam's team winning all 3 sets;
  stored summary said 2-1. Popup now renders the truth (3-0).
  Same pattern applied to several other UAECF-created matches
  where the stored summary had drifted from the actual play.

## How this class of bug arose

Historically `setsA/setsB/winner` were written independently at
End Match time. A stray SET+ tap during play — against a side
that was momentarily ahead mid-set but ultimately lost — could
commit a phantom set that persisted after the actual set closed
and points reset. Combined with MatchEditModal accepting
independent typed values, a divergent record could be created and
survive. This release closes all three doors.

## Migration notes

- No RTDB schema changes, no rule changes, no forced data
  migration. The read-time reconcile heals display without
  touching the record.
- **APK bump** (versionCode 58 → 59, versionName 3.4.10 → 3.4.11)
  for TWA parity; wrapper otherwise unchanged.
