# Carromscore v3.4.3

Broadcast overlay now renders on the `/live/?mid=X&view=overlay`
route too — the OBS Browser Source URL the umpire actually uses
for remote-broadcast setups.

**APK SHA-256**: `655d289c58e1f98dd49ac93e5404f6b9b836c4716d54a42e4f86153f829a385a`

<!-- apk-required: false -->

Web changes only — existing v3.4.2 APK installs auto-update on
next launch. TWA bumped for parity; fresh APK download is optional.

## What changed

- **`/live/?mid=X&view=overlay` now renders the v3.4.2 overlay
  design.** Previously it was still rendering `LiveScoreboardView`
  — the older boxed-tile scoreboard — because v3.4.2 only touched
  `OverlayBoard.svelte` (the `/score/?view=overlay` route used by
  single-machine setups). Remote-broadcast setups pointing OBS at
  a `/live/` URL never saw the redesign.
- **`OverlayBoard` accepts an optional `record` prop.** When the
  parent (LiveLobby) hands it a `LiveRecord` from the Firebase
  `/live/{mid}` subscription, the overlay renders from that
  record and reacts to live updates via a `$effect`. When the
  prop is absent (the `/score/` route), the standalone
  URL-config + localStorage path from v3.4.2 stays exactly as it
  was.
- **Both overlay routes now share one component and one visual
  design.** `/score/?view=overlay` (single-machine, localStorage-
  driven) and `/live/?mid=X&view=overlay` (remote, Firebase-driven)
  differ only in their data source.

## Migration notes

- **No RTDB rule changes.** The `/live/{mid}` payload shape is
  unchanged — the overlay just reads the existing fields.
- **No schema changes.** No new tournament / match fields.
- **APK bump** (versionCode 50 → 51, versionName 3.4.2 → 3.4.3)
  for TWA parity; wrapper otherwise unchanged.
- **Existing `/live/?...&view=overlay` OBS Browser Sources start
  showing the new design automatically** on the next page load —
  no URL changes, no OBS reconfiguration required.
