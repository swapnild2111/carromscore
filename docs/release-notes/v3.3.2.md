## What changed

**publishLive → visible.** `src/lib/live-sync.ts:publishLive`
used to catch every Firebase write error and discard it. Under
v3.3 rules — where the `/live/{mid}` `.validate` requires
`updatedAt` within 60 seconds of the server clock — a device
clock more than a minute off would reject every publish silently.
Match plays fine on the umpire's device; nothing ever appears
under `/live` for the spectator URL or the OBS overlay to
render.

The function now returns `{ ok, error? }`. `ScoreBoard.svelte`
awaits the outcome on every publish; the first failure per
session pops a **"Live broadcast paused — <error>"** toast for 8
seconds. Subsequent identical failures are suppressed to avoid
spamming on every score tap; a successful publish re-arms the
toast so any later denial fires again.

`sync-queue.ts`'s flush path keeps the item queued on `ok: false`
instead of relying on the (now-removed) silent-throw path.

## Migration notes

- **No breaking changes.** `publishLive` signature widened from
  `Promise<void>` to `Promise<{ok, error?}>` — the only two
  callers (`ScoreBoard.svelte` and `sync-queue.ts`) are updated
  in this release.
- **APK bump** (versionCode 42 → 43, versionName 3.3.1 → 3.3.2)
  for TWA parity; wrapper otherwise unchanged.
