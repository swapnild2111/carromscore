# Carromscore v2.2.9

Source-tree hygiene. No user-visible changes.

## Behind the scenes

- **Firebase Web `apiKey` moved out of the source tree** into a
  build-time environment variable. The value is now supplied by
  the `PUBLIC_FIREBASE_API_KEY` GitHub Actions repo secret rather
  than being committed to `src/lib/firebase.ts`. This satisfies
  generic secret-scanner tooling that matches the 39-char
  Google-API-key regex.

  Real-world security is unchanged. The Firebase Web `apiKey` is
  a public identifier per Firebase's own security model (see
  <https://firebase.google.com/docs/projects/api-keys>); the built
  client bundle still contains it as it must, and access control
  was always enforced by the Realtime Database rules in
  `database.rules.json`, not by the key. What changed is that the
  literal no longer appears in any committed source file.

- **Deleted** `scripts/backfill-tournament-key.js`. The one-shot
  utility already ran against production (19 legacy match records
  patched on 2026-08-14). Kept nothing but a redundant API-key
  literal — removed to reduce future scanner false positives.

## Migration notes

- **No RTDB rule changes.**
- **No breaking changes.** Existing records, existing signed-in
  sessions, existing PWA installs all keep working. Service
  worker's per-build cache key auto-invalidates on next online
  visit.
- **Contributors**: `cp .env.example .env` and fill in
  `PUBLIC_FIREBASE_API_KEY` before running `astro dev`. The
  existing `PUBLIC_BOOTSTRAP_SUPER_UID` variable is unchanged.
