# Carromscore v3.6.0

Tournament-day release. This is the one that turns Carromscore into
a proper tournament tool: pre-created bracket matches with permanent
per-board QR stickers, a printable tournament pack (cover sheet +
one page per board), tournament-level match defaults, a proper
Rounds lifecycle (pending → running → closed), and cross-organiser
alias resolution in AdminPlayers.

## Bracket admin (new)

- **Per-tournament Bracket modal** opened from the tournament row's
  new **Bracket** button. Round chips across the top, add-match
  form (Singles / Doubles toggle, board number, Side A / Side B
  with player autocomplete + country pills), and a table of the
  round's planned matches with status pill (ready / scoring ·
  time-ago).
- **Player autocomplete** on all four name inputs, pulling from
  the same `/players` identity store MatchSetup uses. Tapping a
  suggestion captures the resolved player id so the post-scan
  setup screen renders the flag immediately.
- **Per-match mode toggle** — a tournament defaulted to Singles
  can still hold a Doubles exhibition match without a second
  tournament tag.
- **Invite-only roster gate** — bracket admin refuses to add
  off-roster players in a closed tournament, listing the
  offenders in an inline error. Autocomplete filters to the
  roster too. Open tournaments skip the gate entirely.

## Per-board QR stickers

The scan target is a physical board, not a specific match. Every
board gets one permanent QR sticker, printed once and stuck to the
carrom board for the whole tournament. Umpires scan the same
sticker every round; the app auto-advances to whichever match is
currently assigned to that board.

- **`/planned/{mid}`** — new RTDB node storing pre-created match
  slots. Fields: `mode`, `tournament(Key)`, `round(Key)`,
  `matchOrder`, `board` (1..99), player names + optional resolved
  ids, per-match `cfg`, `createdBy`, `createdAt`, `claimedBy`,
  `claimedAt`. Rule: super or the tournament's organiser writes;
  claimedBy self-writes so the umpire flow works.
- **`resolvePlannedByBoard(tournamentKey, board)`** — given the
  fixed sticker payload, picks the lowest-ordered unclaimed match
  for that board (roundKey then matchOrder). Claimed matches fall
  through as takeover candidates so a re-scan by the same umpire
  resumes their own match.
- **QR URL shape**: `?tournament=<key>&board=<N>`, stable across
  rounds. MatchSetup's deep-link handler resolves to a mid, applies
  cfg, and shows the preview banner — umpire taps Start.
- **Auto-advance**: when a match is scored, `/planned/{mid}` is
  deleted. Next scan of that board's sticker resolves to the next
  round's match automatically. Zero admin work between rounds.

## Print pack (new)

New **🖨 print button** on each tournament row opens the printable
pack in a new tab:

- **Cover page**: brand strip, big tournament name banner, country
  flag (for invite-only), meta grid (Format / Type / # Boards /
  # Matches / # Players), and an alphabetical player roster with
  country flag pills.
- **Board pages**: one per physical board (1..maxBoard), big
  "Board N" header, tournament name, big central QR, scan CTA.

Roster source is the assigned roster for invite-only tournaments;
for open ones, unique names gathered from all planned matches,
resolved against `/players` for country flags.

## Round lifecycle

Rounds now have a proper media-player lifecycle:

- **Pending** — freshly added, `state='open'` but no `startedAt`.
  ▶ Start enabled, ⏹ Close disabled.
- **Running** — organiser hit Start. `startedAt` stamped.
  ▶ Start disabled, ⏹ Close enabled.
- **Closed** — organiser hit Close. Terminal — no reopen. New
  match creation excludes closed rounds. Add a fresh round with
  a new label if you need to keep scoring.

Close is confirm-gated. Legacy rounds (no `startedAt`) render as
pending; the organiser can start or close them directly.

## Tournament settings dialog

Clicking the tournament name opens a slimmed edit dialog:

- **Name / Type (Open vs Invite-only) / Country** — unchanged
  fields.
- **Match defaults** — new fieldset with Mode / Best of / Points
  target / Max boards (0 = unlimited). Seeded with sensible
  tournament values (bo3 / 25 / 8 / singles) so the numbers you
  edit are the numbers that get used. Every planned match created
  under this tournament inherits these; MatchSetup prefills the
  score-setup form when the tournament is picked. Umpires can still
  override per match.

The old inner "Rounds / Bracket / Assigned players" launcher block
is gone — those are direct row buttons now.

## Tournament row restructure

Row layout:

```
[Name (click to rename)]  [OPEN/INVITE-ONLY]  [country]  [last active]
[ Players (N)  Rounds (N)  Bracket (N)  🖨  🗑 ]
```

- **Players** only for closed tournaments; count from
  `assignedPlayerIds`.
- **Rounds** count from `tournament.rounds`.
- **Bracket** count from a live `/planned` aggregation.
- **🖨** opens the print pack (highlighted, accent tint — this is
  the tournament's primary output action).
- **🗑** confirm-gated delete (unchanged).

## AdminPlayers — full roster, own-only writes, cross-organiser aliases

Organisers now see the **full** roster (everyone's players), not
just their own. Row-level Edit / Delete stay gated to
`createdBy === myUid`. Rows an organiser can't manage get a muted
grey **read-only** chip so the missing buttons don't read as a bug.

The alias flow (Add dialog → conflict resolution) now works
cross-organiser: typing "S. Deshpande" can be aliased onto Swapnil
Deshpande's canonical record even if a different organiser created
it. RTDB rule change: `/players/{id}/aliases` and `.../normalisedIndex`
`.write` widened to allow super OR the record's `createdBy` OR any
signed-in organiser. Canonical identity (name, country) still owned
via the parent `.write` rule — unchanged.

## MatchSetup — bracket-scan preview banner

When MatchSetup opens via a bracket QR (`?planned=<mid>` or
`?tournament=<key>&board=<N>`), it renders a richer preview banner
above the setup form:

- **Bracket** pill + tournament name + round
- Players (with partners for doubles)
- Format line — Singles/Doubles · boN · target X · max Y boards

Umpire spots a wrong pick before Start without reading the small
form below. Edit any field, then Start.

## Bug fixes

- **PrintBracket "Loading…" hang** — two root causes: a
  `roundKey.localeCompare` on undefined in the /planned subscribe
  callback throwing silently, and mixed `$derived` call sites in
  the template. Fixed with `?? ''` coercion in the sort, a parallel
  one-shot `get()` fallback so either data path unblocks the render,
  an 8-second safety timeout, and standardisation on
  `$derived.by(() => ...)` for computed values with bare reads in
  the template.
- **Bracket modal opened underneath the Edit dialog** — z-index
  400 vs 90 collision. Lifted bracket-backdrop to 500.
- **`?planned=<mid>` QR opened /score/ directly** — cfg was empty,
  match archived as "First Player" vs "Second Player" with no
  visible entry in Live. QR now points at the app root
  (MatchSetup) so the setup preview + Start button run before
  ScoreBoard.
- **Drawn set in bo3+ ended the match** — `handleDrawChoice('draw')`
  now checks totalPlayed < bestOf and rolls to the next set;
  `setWinners` widened to include 'draw'.

## Migration notes

- **New RTDB rules required** — publish `database.rules.json`
  before this release lands. Additions:
    - `/planned/{mid}` node with per-field validators (mode,
      tournamentKey, round(Key), matchOrder, board 1..99, player
      names + resolved ids, cfg, createdBy, createdAt, claimedBy).
    - `tournament.defaults` sub-node (mode / bestOf / pointsTarget /
      maxBoards) with range validators.
    - `round.startedAt` — non-negative number.
    - `/matches/{id}/setWinners/$idx` accepts `'draw'` alongside
      `'a'` and `'b'`.
    - `/matches/{id}` `.write` update path widened so the record's
      `createdBy` can edit their own match (with tournament fields
      immutable).
    - `/players/{id}/aliases` and `.../normalisedIndex` `.write`
      widened to any signed-in organiser (cross-organiser alias).
- **New MINOR version** (3.5.5 → 3.6.0) reflects the tournament-
  admin scope: new data model (`/planned`), new user-facing flow
  (bracket → print → scan → auto-advance), new admin surface (row
  buttons, defaults dialog, round lifecycle). No breaking data
  changes; legacy match records / rounds / players continue
  working.
- **APK bump** (versionCode 65 → 66, versionName 3.5.5 → 3.6.0)
  for TWA parity; wrapper otherwise unchanged.
