# Carromscore v2.2.7

Tournament organisers can now edit scores of any match played
under their tournaments — no super-admin required. Plus a few
small display + CI fixes.

## Added

- **Organiser edit access.** If you've been assigned as an
  organiser for a tournament (by a super-admin, via /admin/
  Roles), you can now edit scores of any match in that
  tournament. Open the Lobby's History tab → the ✎ pencil
  appears on cards tagged with your tournament. Tap → edit
  points / sets / board notes → Save. Scope is strictly
  per-tournament: you can't re-tag matches into or out of
  your tournament, and matches from other tournaments stay
  invisible to your edit rights.
- **Deep-link for history archives** (existed in v2.2.6, worth
  mentioning again as it complements the organiser workflow):
  `/live/?tab=history&match=<id>` opens a specific match's
  sheet dialog directly. Useful for organisers correcting a
  score reported over WhatsApp.

## Changed

- **Footer pill: "Sign in" (was "Admin").** Not every user is
  an admin. The pill still leads to Google sign-in; once you're
  signed in, it becomes your avatar + name with a Sign-out menu.
- **Board-by-board scorecard shows up correctly for older
  records.** A few match records (typically admin-created or
  hand-corrected) had `set` values that didn't match the
  bestOf configuration. The scorecard block silently disappeared
  for them. Now every set present in the log gets its own
  section, so those records render their full board history.

## Behind the scenes

- **RTDB rule update.** The `matches/{id}` write rule now
  authorises organisers via the tournament SLUG (matches the
  actual `/tournaments/{slug}/` node) instead of the display
  name (which pointed at a non-existent path). Backwards
  compatible — the super-admin branch is unchanged.
- **One-time backfill.** All existing match records tagged with
  a tournament had their `tournamentKey` slug field added, so
  organiser edits work on historical data too. Script committed
  as `scripts/backfill-tournament-key.js` for the record.
- **CI safeguard fix.** The workflow's artifact-integrity check
  had a bash path-construction bug that failed every beta
  deploy after the safeguard shipped. Fixed.

## Migration notes

- **RTDB rules must be published in the Firebase console**
  before organisers can save edits (already done for
  swapnild2111's project — same rules for /carromscore/ and
  /carromscore/beta/).
- **No breaking changes.** Existing writes and reads unaffected.
