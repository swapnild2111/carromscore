## Rounds — the whole picture

A real tournament has stages. Before v3.2, all matches under one
tournament collapsed into a flat list — you couldn't ask "how did the
semifinals go?" without eyeballing dates. v3.2 adds a proper
first-class round layer:

- **Admin panel → Tournaments → Rounds** button per row. Add /
  Rename / Toggle-state / Delete. Rounds display in the order you
  add them; the roundKey is derived from the name via the same
  normaliser the tournament key uses.
- **Per-round Open / Closed state.** Close R16 when QF starts so
  the setup picker only offers rounds still accepting matches.
- **Match setup → Round picker** appears when the picked
  tournament has rounds. Free-text with suggestions from the
  tournament's open rounds — the umpire can also type a raw
  string, same posture as the tournament input.
- **Lobby → History tab** groups two levels deep: tournament →
  round → matches. Rounds display in the order you set them.
  Matches with no round tag fall into an italicised *Unassigned*
  sub-group at the tail of the tournament. Ghost rounds (round
  record deleted but match still tagged) get their own bucket
  after the known rounds.
- **Lobby → Reports tab** renders a per-round accordion below the
  combined view — player summary + matches table per round.
  Combined-view charts stay at the top, unchanged.
- **Optional throughout.** A tournament without any rounds
  behaves exactly like every tournament before v3.2 — flat match
  list, no round picker at setup, no accordion in reports. Pre-
  v3.2 archives display the same too.

## Data model + rules

New RTDB sub-node: `/tournaments/{key}/rounds/{roundKey}` with
`{ name, order, state, createdAt }`. Same write-auth as
`organisers` — super or listed organiser of the parent tournament.
Match records gain optional `round` / `roundKey` fields alongside
the existing `tournament` / `tournamentKey` pair, denormalised in
lockstep so the lobby can render without a tournament-record read.

## Migration notes

- **RTDB rules changed.** The published rules need to be updated
  before matches with round fields can archive. Applied changes:
    - `/tournaments/{key}/rounds/{roundKey}` — new node with its
      own write-auth + validators.
    - `/matches/{id}` — `round` and `roundKey` fields
      allowlisted (both 1–60 char strings).
  Backwards-compatible for reads — old records without the fields
  still validate.
- **No breaking client changes.** Existing archived matches keep
  working; they simply carry no round tag. New archives carry
  the round tag when the umpire picked one at setup.
- **APK bump** (versionCode 39 → 40, versionName 3.1.0 → 3.2.0)
  for TWA parity; wrapper otherwise unchanged.
