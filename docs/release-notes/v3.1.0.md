# Carromscore v3.1.0

Country identity, tournament open/closed lifecycle, deciding-board
correctness pass, and a large batch of scoring-flow bug fixes reported
during the beta soak.

**APK SHA-256**: `241fca401db471aa3b6d66f3717da0a1b7746e051c39d24d59c099be93030ec0`

<!-- apk-required: false -->

Web changes only — existing v3.0.1 APK installs auto-update on next
launch. New installs from `/releases/latest` should grab the fresh
APK.

## Country identity for players

Every player record now carries a country. The admin panel's Add
players flow takes a batch country; the picker on Home shows a flag
pill beside each suggestion; the scoreboard header renders the flag
inline with each singles player's name.

- **Namesakes from different countries coexist as separate records.**
  "Swapnil Deshpande (DK)" and "Swapnil Deshpande (SE)" resolve to
  distinct player ids. Picker shows them as two rows. Match archives
  attribute each game to the correct namesake.
- **Same-player-vs-self is blocked at Setup** with an inline banner
  ("Player A and Player B are the same player") and a disabled Start
  button. Applies to both singles and doubles (no player on both
  teams, no player twice on the same team).
- **Edit Player dialog** in the admin panel lets you correct or add
  a country on any existing record. Alias list is editable in the
  same dialog. Save at the bottom commits both fields at once —
  no per-field save.

## Tournaments: open/closed lifecycle

Tournaments now have a state: **open** (default) accepts new matches,
**closed** rejects them. Home form warns when the picked tournament
is closed. Admin panel toggles state per tournament.

- Organiser assignment stays independent of state — closed
  tournaments can still be edited by their organisers.
- Closed-warning is advisory; the umpire can override on the Home
  form and start the match anyway (physical carrom clubs sometimes
  reopen a bracket after the closing tap).

## Scoring: deciding-board correctness

The bo3 deciding-board flow had a bag of state-leak bugs across
sets. Cleaned up:

- **Deciding-board label + extra board slot** now reset on
  set-transition. Prior: a set-1 decider extended maxBoards for
  every subsequent set too, so set 2 played 3 boards with the
  decider banner still on top.
- **Set 2 tied at cap now offers the decider prompt**, not
  "wins 0-1". Match-clinch check runs before set-lead check in
  `endMatch`.
- **SET+1 on a tied set is blocked with guidance** ("tap End
  Match — you'll get the decider option") so umpires don't have
  to guess the next tap.
- **Auto-end on set clinch.** When one side reaches ⌈bestOf/2⌉
  sets, the match ends automatically — no need to play a
  redundant third set of a 2-0 bo3.
- **Decider break assignment** derives from `boardLog[last]`
  rather than the current chip position, so BOARD+1 before End
  doesn't flip the decider's breaker to the wrong player.
- **Break on Set 2** now rotates from Set 1's opener (real
  carrom: the other side breaks the next set), independent of
  who broke the last board.

## Scoring: mid-match swap re-enabled, always

Swap was over-restricted in v3.0 — locked out once any board was
recorded. Real carrom needs a swap at explicit boundaries (start of
set, halfway point of a decider, or just "we want to change sides
now"). Rewrote the flow:

- **No time restrictions.** Umpire can tap Swap at any point in
  the match.
- **Points travel with players.** Both cumulative set points and
  per-board running deltas swap sides, so a mid-board swap doesn't
  corrupt the boardLog when BOARD+1 finally captures the row.
- **Queen + break chip travel with players** too, so the visual
  assignment stays anchored to the person who actually holds
  each token.

## Scoring: score-correction edge cases

Two rare-but-real corruption paths reported during soak:

- **Post-BOARD+1 correction on the last board of a match.** Umpire
  tapped BOARD+1, spotted a typo, corrected with a swipe. On End,
  the old code either silently reverted the correction or wrote a
  boardLog row that disagreed with the summary total. End now
  reconciles: the last row's per-board delta is rewritten to match
  the current cumulative totals, so archive summary and recap
  table always agree.
- **Queen +3 validation** (not auto-add). When queen is marked, the
  holder's per-board delta must be ≥ 3, unless it's exactly 0 (the
  opponent won the board despite queen chip marking) or the holder
  was already at the queen-lockout threshold at board start.

## Recap redesign

- All sets appear in the recap table (prior: only set 1, because a
  trim used the per-set board counter as if it were the match-total).
- Sticky recap header — mode / players / Close button stay visible
  while the table body scrolls on a narrow phone.
- Close dialog copy fixed to differentiate "match ended, safe to
  close" from "score would be discarded".

## Small UX

- DSEG7 digit font is now preloaded on the score page so digits
  render in the correct font on the first paint after a hard
  reload — no Courier New flash.
- Home picker fills in flags for players whose local roster row
  predates their country being set on the identity store.
- Home picker's `{#each}` key includes country so same-name-
  different-country rows don't collapse to one at render time.
- Reset button hidden from casual mode; Admin Live tab shows an
  ENDED chip on any match that closed while the tab was open.
- Admin Live matches: player-name-first rows (holdover from v3.0.1
  redesign that landed in main during the cycle).

## Migration notes

- **RTDB rule change**: `players/$playerId/country` is now an
  optional string ≤40 chars. Backwards-compatible — old records
  without the field still validate.
- **RTDB rule change**: `tournaments/$key/state` is optional
  ("open" | "closed"); missing → open. Also backwards-compatible.
- **No breaking client changes.** Match archives written by v3.0.x
  clients keep working (they simply don't carry per-side country
  metadata). New archives carry it.
- **APK bump** (versionCode 38 → 39, versionName 3.0.1 → 3.1.0)
  for TWA parity; wrapper otherwise unchanged. Existing v3.0.1 APK
  installs still work — they'll just show `v3.0.1` in the version
  pill until the user grabs the new APK from `/releases/latest`.
