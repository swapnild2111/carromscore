# Carromscore v3.0.0

Big release. Two headline features (offline-first scoring; organiser
admin panel), plus a lot of quality-of-life work throughout.

## Offline-first match scoring

Carromscore now works with no internet at all. Start a match, play
all boards, End it — everything renders and records locally. When
the network returns, in-progress matches publish to the live server
and ended matches archive to history. No lost work, no failed
writes, no "please try again."

- **Amber banner** at the top of every screen when the app can't
  reach the network. Matching grey lobby chip on the home screen
  makes the state obvious at a glance.
- **Sync queue on device** (localStorage). Survives page reloads on
  the same device. Live payloads coalesce by match id (per-tap
  volume doesn't bloat storage); match archives append.
- **True-timestamp preservation.** A match ended offline gets
  archived with its real `endedAt` on flush, not a re-stamped-now
  value.
- **RTDB rule change** dropping the 5-min `endedAt` guard on
  `/matches/{id}` create, so late flushes replay honestly. Anti-
  forgery on writes is still enforced via `createdBy` + auth checks.
- **Sign-in gate.** The signed-out pill is disabled offline (Google
  sign-in requires internet). Sign in *before* the outage if you
  want your match attributed.

See [docs/features/offline-mode.md](../features/offline-mode.md)
for the full guide.

## Organiser admin panel

Tournament organisers now have their own admin surface. Sign in and
you get the Open admin panel link in the account menu.

- **Players tab.** Bulk-add via comma-separated or newline-separated
  input. Per-conflict resolution UI: merge into existing / save as
  new / skip. Reuses the fuzzy-name-match ranking that powers the
  setup autocomplete.
- **Tournaments tab.** Create / rename / delete tournaments you
  organise. Manage co-organisers (add or remove peer organisers on
  your events). Search bar for filtering.
- **Live matches tab.** See all live records; delete the ones for
  your tournaments (or any you personally published).
- **History cleanup tab.** Same treatment for archived matches —
  delete only what belongs to your tournaments (or your own
  recorded matches).

Super-admins still get everything they had before, plus Roles
management and the Audit log.

**Per-row auth gating.** Delete buttons and selection checkboxes
hide on rows the current user can't act on. No more clicking a
button just to see a "permission denied" toast.

**Fixed-height scrollable lists.** Every admin tab's list now
scrolls inside a bounded box — the tab bar and toolbar stay pinned
at the top, no matter how long the list.

## Cleaner data ingress

Two long-standing sources of duplicate records in `/players/` and
`/tournaments/` are turned off:

- **Match End no longer auto-creates `/players/` records.** Names
  the umpire types but doesn't pick from the autocomplete now go on
  the match record as a raw string. The admin panel is the only
  path that creates canonical player records. Result: fewer
  "V Kumar" / "V. Kumar" / "V.Kumar" near-duplicates for admins to
  merge later.
- **Match Start no longer auto-creates `/tournaments/` records.**
  The tournament string on the setup form rides through to
  `/matches/{id}.tournament` for lobby grouping, but no
  `/tournaments/{key}` entry is materialised. Admins create canonical
  tournaments explicitly to attach organiser privileges.

Both are backwards-compatible: existing records are untouched, and
the lobby's group-by-string bucketing continues to work whether the
canonical entries exist or not.

## Security fixes

- **`/live/{mid}` delete is now auth-gated.** Previously anyone with
  a valid-shape mid could delete any live record. New rule: super OR
  organiser of the record's tournament OR the umpire who published
  (via `createdBy`). Anonymous publishes remain deletable only by
  super.

## Quality-of-life

- **Home form: Mode section moved above Match rules.** Mode drives
  the rules-block shape (Practice hides Points, relabels Boards) —
  picking Mode first means the rules inputs show sensible defaults
  the first time.
- **Help tooltips** on the Mode and Tournament fields — hover on
  desktop, tap on mobile.
- **Sign in label is consistent** across all footers (home, lobby,
  admin). The dropdown now offers "Open admin panel" for organisers
  as well as super-admins.
- **Cold-start banner flash fixed.** The offline banner no longer
  briefly appears on a fresh page load when the app is actually
  online. (Root cause: Firebase's SDK emits a synchronous `false`
  on connectivity subscribe before the WebSocket handshake
  completes; we now swallow that during the boot window.)
- **Signed-in avatar reliability.** Added `referrerpolicy="no-referrer"`
  to the Google avatar `<img>` so Chrome's Opaque Response Blocking
  doesn't nuke it on some origins.
- **Service worker no longer intercepts cross-origin requests** —
  third-party assets (avatars, Firebase RTDB long-poll) go straight
  to network, which is where they'd end up anyway.

## Migration notes

- **RTDB rule changes** published to Firebase console over the
  course of the release:
  - `/matches/{id}` create validator: `endedAt > now - 300000` guard
    dropped.
  - `/matches/{id}` schema: `aName` / `a2Name` / `bName` / `b2Name`
    string fields allowlisted (raw player names for the soft-archive
    path).
  - `/live/{mid}` write: DELETE now gated to super / organiser /
    creator. Create + update stay permissive.
  - `/tournaments/{key}` write: organiser of the tournament can now
    rename / delete / manage co-organisers, in addition to super.
- **No breaking client changes** — existing records, existing signed-
  in sessions, existing installed PWAs all keep working. Old
  behaviour (auto-create on End / Start) is off; old records
  written under the old behaviour are unaffected.

## Behind the scenes

- Slice-by-slice ship on beta (B1 through B7 plus a handful of
  small fixes). Every slice was smoke-tested on beta before the
  next started, and rule changes went to Firebase before the code
  that depended on them.
- ~40 commits since v2.2.9. Extensive churn in admin-side
  components; core scoring surface (ScoreBoard.svelte, MatchSetup)
  mostly untouched except for the offline-mode routing changes.

## Not in this release

- **Cross-device offline sync.** Second-tab and second-device views
  of an offline match still require the umpire's device to reach
  Firebase first. Inherent limitation of a Firebase-only backend.
- **Auth mid-outage.** Google sign-in requires network. Sign in
  before the outage.
- **Test suite.** Vitest for pure logic and Playwright for E2E is
  the next major project — targeted for v3.1.
