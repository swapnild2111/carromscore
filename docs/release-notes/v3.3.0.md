# Carromscore v3.3.0

Organisers are now a first-class role. Super onboards someone once;
from then on they create their own tournaments and players and
manage what they created — no more per-tournament "assign this
UID" step. Own-only auth is enforced at every mutation surface
(admin UI + RTDB rules), so two organisers can share the app
without stepping on each other's records.

## What changed for organisers

**Onboard once, self-serve after.** Super pastes an organiser's
Gmail into `/admin/` → Roles → Organisers → **Onboard as organiser**.
The recipient signs in and immediately sees the admin panel with:

- **Tournaments** they can create, edit, delete — all with full
  control over rounds, closed/open state, assigned players, and
  every match tagged under them.
- **Players** they can create, edit, delete — but only records they
  created. Someone else's players still show up in pickers and the
  admin list (read is public), but the Edit/Delete affordances hide
  for records the organiser didn't create.

Super still sees everything.

## What changed for super

Roles tab is simpler:

- **Onboard organiser** — Gmail input + single button. No more
  per-tournament chip picker.
- **Revoke organiser** — inline "Confirm revoke" on each row.
  Revoking doesn't delete their tournaments; those become super-
  only from then on.

## Tournament admin UX

Every tournament row is now just **Edit** + **Delete**. Rounds and
Assigned Players (closed tournaments only) move inside the Edit
dialog as launch buttons at the top of the modal. Fewer things to
scan on the row list; the dialog collects everything that belongs
to one tournament in one place.

## Data model

- **New RTDB node**: `/organiserRoles/{uid} = true`. Mirrors
  `/adminRoles/{uid}`'s shape — super-only write, auth-only read.
- **`/tournaments/{key}/organisers` is deprecated.** The rules
  block writes from anyone but super now; the client no longer
  reads or renders it. Existing legacy data stays writable-by-
  super and readable-by-anyone until a follow-up cleanup pass.
- **Own-only auth** is derived from the existing `createdBy` field
  on `/tournaments/{key}` and `/players/{id}`. Both fields have
  been part of the schema since v3.0 — this release just makes
  them the auth signal.

## Migration notes

- **RTDB rules changed.** Publish `database.rules.json` before
  soaking end-to-end. The new organiser role can't onboard anyone
  otherwise.
- **Anonymous tournament creation is dropped.** In v3.2 the RTDB
  rules allowed anonymous first-time `/tournaments/{key}` writes;
  v3.3 removes that branch. Match-end tag creation never used it
  after v3.0-B3 anyway, so the surface change is only about the
  admin add-tournament flow being auth-gated.
- **Anonymous player creation is dropped**, same reasoning. The
  admin panel was already the only creation surface after v3.0-B2.
- **Existing per-tournament organisers.** At time of release only
  one organiser was onboarded via the legacy per-tournament map,
  and they were already inactive. Super onboards them (or their
  replacement) globally via the new Roles flow — no automated
  migration was needed. If you're deploying to a fork with more
  legacy organisers, the manual onboarding step is one row per
  uid in `/admin/` → Roles.
- **APK bump** (versionCode 40 → 41, versionName 3.2.0 → 3.3.0)
  for TWA parity; wrapper otherwise unchanged.
