# Carromscore v3.0.1

Patch. One user-reported fix.

## Tournament delete now cascades to child matches

Reported after v3.0.0 shipped: deleting a tournament from the admin
panel left every match tagged under it visible in the lobby's
History tab, still grouped under the deleted tournament's name.
The pre-fix delete only removed the `/tournaments/{key}` record;
the lobby's History grouping reads each match's own `tournament`
field, so those matches kept surfacing.

Fix: deleting a tournament now cascades — the tournament record
plus every match tagged with its `tournamentKey` are removed
together. Matches you're not authorised to delete (e.g. an
organiser trying to wipe another organiser's records) are silently
skipped and reported in the summary flash.

- **Confirmation dialog** shows the child-match count before you
  type DELETE: *"This will delete the tournament record and N
  tagged matches. Matches you're not authorised to delete will be
  skipped."*
- **Bulk delete** applies the same cascade per tournament, serially.
- **Outcome banner** reports both counts: *"Tournament deleted · N
  matches removed"* on success; partial failures include a
  *"matches skipped"* count.

Everything else in v3.0.0 unchanged.

## Migration notes

- **No RTDB rule changes.** The cascade uses the existing
  `/matches/{id}` delete rule, which already enforces
  super / organiser / creator authorisation per record.
- **Existing matches tagged under previously-deleted tournaments
  stay visible** — this fix only affects new tournament deletes
  going forward. If you want to clean up matches from tournaments
  you deleted before v3.0.1, delete each match individually from
  the History cleanup tab, or ask a super-admin to bulk-delete
  them for you.
