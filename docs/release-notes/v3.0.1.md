# Carromscore v3.0.1

Patch bundling one bug fix, one admin-UX refresh, and three scoring
rule enforcements. Same tag as the initial v3.0.1 ship — the APK
and release notes have been rebuilt to include everything.

**APK SHA-256**: `7684e5ba05b0095f9a0bf971cb10132b358ccaa261fc7a6ba52c842e8664b37e`

The APK is byte-identical to the initial v3.0.1 build — the TWA
wrapper points at the web URL, so web-only changes (redesigns +
scoring rules) don't affect the Android bundle. Existing v3.0.1
APK installs will auto-pick-up the new web bundle on next launch.

## Tournament delete now cascades to child matches

Reported after v3.0.0: deleting a tournament from the admin panel
left every match tagged under it visible in the History tab, still
grouped under the deleted tournament's name.

Fix: deleting a tournament now removes the record **and** every
match tagged with its `tournamentKey`. Matches you're not
authorised to delete (per RTDB rules) are silently skipped and
reported in the outcome summary.

- **Confirmation dialog** shows the child-match count before
  DELETE: *"This will delete the tournament record and N tagged
  matches."*
- **Bulk delete** applies the same cascade per tournament.
- **Outcome banner** reports both counts: *"Tournament deleted · N
  matches removed"*.

## Admin Live matches: player-name-first rows

The Live tab used to lead with the record's mid slug
("z5xnat singles ...") — cryptic vs the History tab's
"singles · Tournament / Alice vs Bob" shape. Redesign:

- Title row: `[mode chip] [tournament chip] updated Xh ago [LIVE/stuck]`
- Body: **Player names in the primary text colour**.
- Meta line: `mid <slug> · by <umpire name / uid / anonymous>`.

`createdByName` is now denormalised onto `/live/{mid}` at publish
time so organisers can see who published each record without needing
super-only access to `/users`. Anonymous publishes show
*"anonymous"*; signed-in publishes with an empty Google displayName
fall back to a uid-slice chip.

## Scoring rules — ICF enforcement in the app

Three carrom-rules previously enforced by umpire convention only
are now enforced by the scoring UI. Bad-tap protection without
changing the umpire's model of the game.

- **Per-board cap of 12 points.** ICF ceiling: 9 opponent-side
  pucks × 1 pt + queen coverage 3 = 12. Tapping past 12 on the
  current board is blocked with a *"Max 12 points per board"*
  toast — the umpire probably meant to tap BOARD +1. Negatives
  (undo) still work.
- **Queen lockout threshold is now dynamic** — derived from
  `pointsTarget - 3` rather than the hardcoded 22 (only correct
  for the 25-target default). Correct for any target:
  25 → 22, 20 → 17, 15 → 12.
- **One side scores per board.** Real carrom: pockets belong to
  whichever side finishes with the queen covered. Once side A has
  scored on the current board, side B's POINTS taps are blocked
  with a *"Only one side scores per board"* toast until BOARD +1
  or side A is zeroed out. Prevents a mistap from producing
  impossible board records.

Practice mode is unaffected — these rules apply only to the
versus-mode scoring path.

## Migration notes

- **RTDB rule change** (published to Firebase console during the
  cycle): allowlist `createdByName` on `/live/{mid}`. Strict
  relaxation — old records without the field still validate.
- **No other rule changes.**
- **No breaking client changes.** Existing matches, existing
  installed PWAs, existing signed-in sessions all keep working.
