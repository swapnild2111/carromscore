# Carromscore v3.5.0

Big polish + correctness release. Two areas got real attention this
cycle: the scoring lifecycle around SET+/− and swaps (concession
prompts, symmetric rollback, per-set winner credit that survives
swaps and concessions), and the History + Reports surfaces (new
table view, filters, sortable columns, shareable URLs, Reports
podium + tournament-selection rewrite).

## Scoring lifecycle

- **Concession prompt on SET+1**. Tapping SET+1 while the set
  hasn't reached a natural end (winner side below `pointsTarget`
  and board count below `maxBoards`) pops a confirmation: *"Set
  not yet finished — is X conceding this set to Y?"* Real carrom's
  only legitimate reason to end an in-progress set is a
  concession; this stops accidental taps from silently closing a
  running set. Deciding-board flow is exempt.
- **Hard stop on match clinch**. `isMatchDecided()` now returns
  true the moment one side reaches ⌈bestOf/2⌉ sets — not only
  after End Match is tapped. Freezes POINT+, BOARD+, SET+, and
  queen-toggle on a clinched match; negative deltas remain enabled
  so a mistakenly-credited winning set can be undone with SET-1
  (which re-enables scoring).
- **Symmetric SET+/− rollback**. Tapping SET-1 after a SET+1 now
  fully reverses the SET+1's side-effects (boardLog snapshot,
  points/board/queen/break reset, decider state) IF no
  intervening state-mutating action happened. The umpire can
  actually undo a stray SET+ instead of leaving a phantom row
  behind. Reported 2026-08-30 on `-P0GOCEaXTIC7ryRzFO_` — that
  class of corruption is gone.
- **Swap-sides now flips boardLog + cfg identity too**. Previously
  swap only flipped the live sideA/sideB counters; historical
  boardLog rows stayed labelled under pre-swap seats, so the
  recap popup could show *"Set won by Swapnil"* for a set Yuvaraj
  actually won pre-swap. Now every seat-labelled data point gets
  flipped in sync on every swap.
- **Swap-sides prompt after SET+1** opens a new set. Real-carrom
  physical seat swaps between sets are common; the app used to
  silently keep sides put. Now the umpire is asked, Yes runs the
  same `swapSides()` action.
- **Ordered per-set winner credit** (`setWinners`) written to the
  match record. Fixes concession sets where the losing side had
  more per-set points on paper but the credit went to the other
  side — the popup's "Set won by X" ribbon now reflects the
  credited side, not the higher-scoring side. Backwards compatible
  with legacy records via boardLog-total fallback.
- **Write-time heal** — `finishMatch` and `updateMatch` cross-check
  the caller-supplied `setWinners` against boardLog totals and
  rebuild if inconsistent. Prevents divergent records from ever
  landing on disk regardless of what the client sends.

## History tab

- **Table view is now the only view**. The card grid is gone.
  Table has sortable columns (Ended · Mode · Side A · Side B ·
  Sets · Points · Boards). Row click opens the popup.
- **Filter bar**: player-name search + mode dropdown + tournament
  dropdown + date-range chips (7d / 30d / 90d). Applies to the
  table live. Gold-tint highlighted so it reads as the primary
  scoping control.
- **Share button in the history-match popup header**. Copies a
  deep-link URL that opens the same match in the same popup for
  anyone who clicks it. The per-card 🔗 button that vanished
  with the table view is back — where users are actively looking.
- **Shareable URLs**: `?tab=history&hSearch=Azam&hMode=singles&hDays=30`
  — every filter round-trips through the URL. Paste a link,
  recipient lands on the same filtered view.
- **Clear button** appears whenever any filter is off default;
  one click resets search + mode + tournament + date + sort back
  to the default (Ended DESC).

## Reports tab

- **Podium is the FIRST tile** in the stat row: 🥇 · 🥈 · 🥉
  medal-first per row with the player name to the right and win
  count on the far right. Rank 1 gets a soft gold glow.
- **Tournaments count** joined Matches / Players / Boards as a
  fourth summary tile.
- **Compact filter bar** replaces the old wide tournament chip
  strip: player-name search + mode dropdown + tournament dropdown
  + round dropdown (only when the tournament has rounds). Same
  gold-tint highlight as the History bar.
- **Sortable Leaderboard + Matches** tables. Every column header
  is sortable. Sort keys persist to localStorage.
- **Bar charts removed** — the Leaderboard table covered every
  use case they had.
- **Shareable URLs**: `?tab=reports&tournament=Denmark+Ranking&round=quarter-final&rMode=doubles`
  — tournament + round + mode + search all round-trip.
- **Empty `tournament=` param** encodes the Default (untagged)
  bucket, distinct from "no tournament picked yet."

## Popup polish

- **Aggressive banner-hide on resume** when Chrome mobile
  suspends the tab. `navigator.onLine=true` on foreground resume
  hides the banner immediately; Firebase catches up in the
  background.
- **Winner-label suppression for in-progress sets** in the
  Scores popup — a set doesn't show "won by X" until it's
  actually done.
- **Sticky-band scroll fix** in the match popup: names + score
  panel no longer sticky, they scroll away with the per-set
  tables as one unit. Eliminates the overlap on scroll that
  affected long names.

## New Scores button

- **Scores button in the score screen's footer** (before Swap).
  Opens the same LiveScoreboardView popup that history + live
  use — mid-match recap of every set so far, without leaving
  the score screen.

## Bug fixes

- Null-hole crashes in the Reports tab when a match had a
  sparse boardLog (RTDB stores arrays as sparse maps, and an
  admin delete leaves a null hole). Guards added to every
  match/boardLog iteration in `lib/reports.ts`.
- Multiple Svelte 5 reactivity fixes in Reports (`$derived` vs
  `$derived.by`, feedback loops between proxy selects, stale
  DOM value on nearby DOM churn). Now handled with one-way
  `$derived` + `onchange` — simplest form, no timing bugs.
- Reports tab now sourced from a single source of truth
  (parent's `reportsSelection` prop) instead of a local shadow
  `$state` that could drift.

## Migration notes

- **No RTDB schema changes**, no rule changes needed for the
  above. (The `setWinners` field on `/matches/{id}` was already
  whitelisted in v3.4.11.)
- **Minor version bump** to 3.5.0 reflects the perceptual size
  of the History + Reports rewrites — cards to table, filter
  bars, podium, new footer button, URL-share. No breaking API
  or data-model change.
- **APK bump** (versionCode 59 → 60, versionName 3.4.11 → 3.5.0)
  for TWA parity; wrapper otherwise unchanged.
