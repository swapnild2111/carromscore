# Carromscore v3.6.1

Patch release on top of v3.6.0 tournament-day launch. Mobile
alignment fixes, better round-lifecycle UX, cross-tab/device auto-
update reconciliation, and a themed confirm dialog.

## Mobile row alignment

Tournament rows and round rows are horizontal flex layouts with
action buttons at the right. On narrow phones the button stack was
overlapping the name / chips column — the country flag chip
painted behind the Players button.

Both rows now `flex-wrap: wrap`. Below 34rem the name column
expands to full width, forcing the action buttons onto their own
line, right-aligned. Desktop layout unchanged.

## Round lifecycle

- **Rename button removed** — click the round name to rename it
  in place. Same affordance pattern as the tournament row.
- **Reopen is back**. v3.6.0 made close terminal (no reopen);
  feedback said accidental closes mid-tournament were unrecoverable.
  Reopen (↩, soft blue) is now shown on any closed round.
  All three state transitions (Start / Close / Reopen) are
  confirm-gated.
- **Themed confirm dialog** replaces the browser's native
  `window.confirm` (which appeared as a purple-tinted popup on
  Chrome). New in-app `askConfirm({title, body, confirmLabel, kind})`
  helper renders a dark themed modal matching the rest of the
  admin dialogs. Backdrop tap and Escape both cancel.

## Cross-tab / cross-device sync

Reported: 'auto updates are somewhere failing — when they add
players / rounds / brackets - changes are reflects across current
screen tabs or across devices.'

Two subscribe→merge paths were add/update-only. Deletes and
field-clears from another tab or device silently left stale rows
in the current tab's memory until page refresh.

- **`tournaments.ts mergeRemote`**: snapshot is now authoritative.
  Local tournaments not in the incoming snapshot get spliced out.
  Absent fields (createdBy / type / country / rounds / defaults)
  are treated as REMOVAL, not "keep local." Null snapshot runs the
  merger too, so a full clear reconciles.
- **`players.ts mergeRemotePlayers`**: remote-gone players
  (`createdAt > 0`) get spliced out. Seed / unflushed players
  (`createdAt === 0`, Wikipedia bundle) are preserved.
- **`AdminTournaments assignedCountByKey`**: was 'load once per
  key, never refresh.' Now re-runs on `tick` / `playersTick` so the
  Players badge on closed tournaments refreshes live when the
  organiser assigns / unassigns in another tab or device.

## Ghost assigned-player IDs

Reported: `Players (3)` badge on a tournament row while only 2
checkboxes were ticked in the Assign dialog; the header also said
"3 assigned." The third id in `/tournaments/{key}/assignedPlayerIds`
pointed at a player that had been deleted from `/players` — the
count included the ghost, but no visible row matched.

- Badge count now filters against `loadAllPlayers()` and stores
  only real IDs. Ghost IDs never inflate the count.
- On dialog open, `startAssign()` sweeps the ghosts: filters them
  out of the local Set AND fires `unassignPlayer` for each so
  they're removed from RTDB permanently. Next open reads the
  cleaned set.

Cleanup runs naturally as tournaments get inspected — no
dedicated migration script needed.
