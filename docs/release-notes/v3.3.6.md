# Carromscore v3.3.6

Setup + admin polish cycle. Resume no longer wipes an ongoing match
to zero; closed tournaments enforce their roster at Start; organisers
can clean up their own stuck live records; the retired Wikipedia
seed is finally out of the picker.

## What changed

- **Resume no longer resets the match to zero.** A reactive-timing
  bug in `ScoreBoard.svelte` let the save `$effect` fire between
  `storageKey` assignment and the localStorage-hydrate block, so
  the first tick wrote a default 0-0-0 state to both localStorage
  and `/live/{mid}` before hydrate could restore the real one.
  New `hydrated` flag guards the save effect until the restore has
  run.
- **Close-and-discard now clears the Resume chip.** The scoreboard
  `exit()` path cleared local score state but never called
  `clearResume()` or deleted `/live/{mid}`, so the umpire returned
  to Home and still saw a Resume banner for the match they'd just
  discarded.
- **Round is required when a tournament has rounds.** Every match
  under a rounds-having tournament now carries a round tag —
  previously an umpire could leave the round input blank and the
  match landed in a nameless bucket in History and Reports. Start
  is disabled with a tooltip and the round picker itself is now a
  native `<select>` (no more free-text with autocomplete — a
  tournament's roster of rounds is short and closed by design).
- **Closed tournaments enforce roster picks at Start.** For a
  closed (invite-only) tournament, every player slot must resolve
  to an id in `assignedPlayerIds` before Start becomes enabled. A
  free-text name — or a name that resolves to a non-roster player —
  now blocks Start with a single per-slot amber pill: "Not assigned
  to this tournament — contact the organiser". Open tournaments
  are untouched (walk-in-friendly by design). Country mismatch
  stays advisory.
- **Reports side names fall back through the record.** The
  per-match Reports table showed "Side A / Side B" placeholders
  when the players store hadn't hydrated in time or the player id
  pointed at a deleted record. `teamName()` in `reports.ts` now
  passes the denormalised `aName` / `bName` / `a2Name` / `b2Name`
  through as `playerName()`'s fallback — same pattern the History
  card already uses.
- **Round chip in admin Live matches + History cleanup.** Every
  admin row that has a round tag now renders it as a chip next to
  the tournament, blue-accent to sit distinctly.
- **Organisers can clean up stuck live records.** Previously,
  `/live/{mid}` delete required super OR ownership of the record's
  parent tournament OR being the record's creator — leaving legacy
  and orphan records super-only. New fallback: an organiser can
  delete any live record whose `updatedAt` is older than the 4h
  stale window. Mirrors the passive `sweepStaleLive` semantics.
  Active records still gate on ownership.
- **Bundled players seed retired.** `public/data/players.json` and
  its loader are gone. The seed shipped country as full names
  ("India") while the rest of the app uses ISO codes ("IN"), which
  produced country-less duplicate rows in the picker. Firebase
  `/players` is the sole source of tournament rosters and picker
  display flags; the per-device history layer still autocompletes
  names typed on this device.
- **Setup polish.** The inline red "Pick a round for this
  tournament" strip is gone (the disabled Start button + tooltip
  is enough). Both "Represents" text boxes are now labelled
  `(optional)`.

## Migration notes

- **No breaking data changes.** No schema fields added or removed.
- **RTDB rules** — `/live/{mid} .write` extends the delete branch
  with a stale-record fallback for organisers. Publish the new
  rules from `database.rules.json` in the Firebase console before
  organisers see the change; the rest of the client still works
  under the pre-v3.3.6 rules.
- **Local device-history layer preserved.** Names typed on a device
  during previous match setups still autocomplete — that's the
  device-local roster, not the retired seed.
- **APK bump** (versionCode 46 → 47, versionName 3.3.5 → 3.3.6)
  for TWA parity; wrapper otherwise unchanged.
