# Carromscore v2.2.0

The first minor release since v2.0 GA. Focused on giving organisers
real reporting, giving umpires a cleaner tie-break flow, and tidying
up the app's shell so the whole product reads as one thing.

## What's new

### Reports tab in the Lobby

Open the Lobby (renamed from "Live" — same button, new label — see
below) and there's a third tab beside Now Playing and History:
**Reports**.

Pick a tournament from the chip picker and you get:

- **Per-player summary** — one row per player who competed, ranked by
  wins (then boards, then points). Matches / Wins / Losses / Draws /
  Boards won / Points scored — the whole picture at a glance.
- **Two bar charts** — wins per player and points per player, hand-
  rolled inline SVG so the app doesn't ship a heavy chart library.
- **Per-match table** — every match in the tournament, sortable in
  its natural (most-recent-first) order. Sets A/B, Boards won A/B,
  Points A/B, Winner. Native browser selection works (drag to select
  rows → paste into Sheets / Excel / Notion).
- **⧉ Copy table** — one tap to copy the table as tab-separated
  values. Pastes cleanly into any spreadsheet or document tool.
- **↓ Download CSV** — plain CSV file with the tournament slug in the
  filename. RFC-4180 compliant, opens in Excel / Sheets on any OS.

Deep-linkable: `/live/?tab=reports&tournament=Silver%20Cup%202026`
opens the Reports tab pre-selected.

**Default tournament auto-selects on open** — no "pick a tournament"
hurdle for casual browsing. Practice records are excluded (they don't
belong to any tournament by construction).

### Practice section in History

Practice records used to lump into the History tab's "Default"
bucket alongside untagged versus matches. That was visually
confusing — different stats (Misses / Boards vs Sets / Points),
different card render. **Now practice runs get their own
collapsible section below the tournament groups** with the same
count badge + expand/collapse behaviour.

### Deciding board on a tied match-end

Real-world umpires often want to play one more board to break a tie
at the end of a match — different regions decide ties different ways.
Previously the End button was disabled at a tie, or the match
auto-committed as a draw.

**Now:** when the match hits `maxBoards` and the score is level, End
opens a two-button chooser:

- **Play deciding board** — un-ends the match, extends `maxBoards`
  by 1 for this session, flips the BREAK chip (rotates on every
  board like real carrom), clears the queen (per-board state), and
  shows a small "⚡ Deciding board" banner. Score the extra board
  as normal; tap End again when done.
- **Call it a draw** — commits the match as a draw right there.

An early End on a tie (below the board limit) still auto-commits as
a draw — that's the umpire's likely intent when they're calling it
short.

**Draw semantics tightened.** SETS no longer auto-ticks +1 on both
sides for a draw (that was a v2.1 quirk that read as "both sides
won a set"). Draws leave the SETS column exactly where it was; a
tied set has no winner, honest reading is honest reading.

### 'Live' → 'Lobby'

The red pill on the home screen used to say "Live". As the /live/
destination grew from ongoing broadcasts into Now Playing + History +
now Reports, "Live" undersold the content inside. **Renamed to
"Lobby"**. Red pulsing dot stays — still signals live broadcasts
inside. URL stays `/live/` so every existing shared link keeps
working.

### Home + Lobby footer parity

The home screen's footer (How to use ⇗ · Feedback ⇗ · Admin, then
version + copyright) now also appears at the bottom of the Lobby.
Version pill removed from the Lobby header. Result: both screens
read as one product. The Feedback popup is now a shared component,
so a change in one place shows up in both.

### Version pill → GitHub release notes

Every version pill in the app (home footer, scoreboard footer, lobby
footer) is now a link to that version's GitHub release notes. One
tap to read what changed in the build you're running.

### Doubles setup: coloured team blocks

In Doubles mode, Team A's block gets a blue tint + border (matching
the side-A pill) and Team B's gets coral (matching side-B). The
setup screen previews the on-scoreboard identity — you can already
tell which team is which colour before the first board.

### Default match config: 1 set × 25 points × 8 boards

For singles and doubles setup. Casual and club-night use is
overwhelmingly single-set; Best-of-3 stays a one-tap preset for
tournament organisers who need it. If you always change bestOf from
3 → 1, this saves the tap.

## Under the hood

- **`src/lib/reports.ts`** — pure computation module. Builds per-match
  rows + per-player summary from an in-memory MatchRecord[]. TSV +
  CSV serialisers. Handles legacy phantom-board records (pre-
  2026-08-09) via the same trim logic as `LiveScoreboardView`.
- **`src/components/reports/BarChart.svelte`** — reusable inline SVG
  chart. Locked viewBox, fluid scaling, per-bar `<title>` for
  tooltips. Under 150 lines.
- **`src/components/reports/ReportsTab.svelte`** — the tab body.
- **`src/components/FeedbackPopup.svelte`** — extracted from
  MatchSetup so home and lobby footers share it.

No new dependencies. No new Firebase paths. Uses the same
`/matches` read the History tab already loads. **No RTDB rule
changes** — Reports is read-only over an already-public tree.

## Migration notes

- **No breaking changes.** All v2.1.x records continue to render
  unchanged.
- **CSV format is stable** — 12 columns, RFC-4180. Feel free to
  build downstream tooling against it; column set is fixed.
- **Rules unchanged** — no republish required.
