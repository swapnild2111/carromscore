# Carromscore v3.4.7

Broadcast overlay overhaul — proper lower-third graphic with per-side
set history, a rounded-box strip, and a handful of design-preview
niceties. Also includes a defensive-render fix for a legacy History
records rendering bug.

## What changed

### Overlay — per-side set-history chips

- **New**: singles/doubles overlay renders each side's per-set final
  points as small chips flanking the strip's outer edges.
  Currently-playing set has a gold border + label; won-set chip
  picks up the side's colour (blue A / orange B); lost-set chip
  fades to muted grey. Unplayed sets read `–`.
- Chips are derived from the `boardLog` in the live payload, so
  they populate live on both `/score/?view=overlay` (localStorage-
  driven) and `/live/?mid=X&view=overlay` (Firebase-driven).
- Toggle off with `?sets=0` on the `/score/` route.

### Overlay — layout polish

- **Rounded-box strip.** The strip renders as a bounded rounded
  panel with a full-perimeter accent-gold border + drop shadow,
  inset 1vw from the viewport edges. Was a bleed-off-the-viewport
  ribbon.
- **Shared diagonal-stripe pattern** across strip / tiles / pills.
  Ties the composition together as one broadcast graphic.
- **Common strip background** (`rgba(11,11,11,0.6 → 0.82)`) so
  cards sit on a coherent ribbon rather than floating over the
  camera feed.
- **Digits sit inside their card** — line-height `0.85 → 1` (the
  DSEG7 glyph was clipping the card border at tight leading).
- **Centre caption reordered** — "3rd SET" instead of "SET 3rd".
- **Digit size trimmed** ~20% on singles/doubles for a less
  frame-dominant broadcast look.

### Overlay design-preview flags

- `?variant=N` (1-5) — switch layout variant on `/score/` only.
  Variants 2-5 are exploratory (corner cards, top ticker, side
  rail, sports scorebug). Default 1 = the polished lower-third.
- `?centre=N` (0-3) — try three per-set-scores centre-column
  designs on the versus overlay. Default 0 keeps the standard
  SET pips + BOARD digit block.
- `?bg=demo` — paints a subtle green tinted checker behind the
  overlay so the umpire can see overlay transparency in Chrome
  (in OBS/Prism the URL never carries this).
- `?demo=1` — seeds a plausible mid-match state (S1 A won 25-16,
  S2 B won 25-12, S3 in progress 18-22) so designs can be
  evaluated without driving a real scoreboard.

### History popup — defensive fix

- **Skips null slots in boardLog.** Firebase RTDB stores arrays
  as sparse maps; deleting a boardLog index via the Firebase
  Console leaves a `null` at that slot. Both LiveScoreboardView
  and MatchEditModal now filter out nullish entries so the
  history popup and Edit modal render gracefully on records
  with such gaps.
- **Composite each-key** on the board-by-board scorecard uses
  `endedAt` timestamp appended, avoiding the
  `each_key_duplicate` crash on legacy records where a set logged
  the same board number twice.

## Migration notes

- **No RTDB rule changes**, no schema changes.
- **APK bump** (versionCode 54 → 55, versionName 3.4.6 → 3.4.7)
  for TWA parity; wrapper otherwise unchanged.
- `?variant=`, `?centre=`, `?sets=`, `?bg=`, `?demo=` flags are
  design-time tools on `/score/` only; they're not threaded
  through the `/live/` route (which is meant for real matches).
- Existing OBS URLs (both `/score/` and `/live/` shapes) render
  the new layout automatically on next page load.
