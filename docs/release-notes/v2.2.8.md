# Carromscore v2.2.8

Four scoring / display fixes reported by an umpire mid-match.
No new features. Recommended for anyone actively scoring
tournaments.

## Fixed

- **SET+1 no longer credits the losing side.** Tapping SET+ on
  the player with fewer points used to silently credit them the
  set anyway; End could then declare the wrong winner (bug: A=8,
  B=10, umpire tapped SET+ on A → A crowned). Now SET+ shows a
  small toast "Only the leading side can be credited a set" and
  refuses. Ties are also refused — score one more point (or use
  End → decider-board) to break them. SET-1 undo works
  unchanged.
- **SET+1 no longer keeps advancing the board counter.** If the
  umpire scored a stray point on the "running board" past the
  board cap and tapped SET+ multiple times, the board counter
  went to 4 → 5 → 6 → indefinitely. Now the first tap correctly
  credits the set; subsequent taps are idempotent. At the board
  cap, stray points also silently roll back to the last
  committed baseline instead of appending a phantom row.
- **Board-by-board scorecard column showed multiples of the
  actual score.** The `SCORE` column (cumulative running total)
  was rendering as N × actual (e.g. 40 instead of 8, 50 instead
  of 10) whenever the popup received a reactive update.
  Underlying data was fine — display only. Refactored to a pure
  computation; no more render-time side effects.
- **BREAK chip is now locked after scoring begins.** The chip
  is tappable during the toss (before any points / boards) so
  the umpire can set who won; from the first point onwards it
  becomes a read-only indicator, driven automatically by
  BOARD+1 (per real-carrom rule) and set boundaries. A stray
  tap after the first board used to swap the archived break
  side out of sync.

## Migration notes

- **No RTDB rule changes.**
- **No breaking changes.** Existing records unaffected.
- Umpires mid-match should hard-refresh once for the new SW to
  activate (usually happens automatically on next app open).
